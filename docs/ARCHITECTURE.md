# Cove

Cove is a custom, lightweight deployment control plane, not a wrapper around another hosting panel.

## Agreed design

- Exactly one main node hosts the dashboard, API, PostgreSQL configuration database, and durable job queue.
- Worker nodes run Docker/Compose workloads. There is no artificial node limit; capacity depends on control-plane resources.
- The main node initiates SSH connections to workers. Workers need no public management API. Private networks, VPNs, and eventually jump hosts can provide reachability.
- Each worker uses a small Go executable with structured requests and responses. Long-running operations must persist locally and survive SSH disconnection. Reconnection reconciles operation IDs before retrying.
- The main node can also host workloads using the same executable through a local transport, without SSH to itself.
- Add node generates an expiring one-time setup command. Bootstrap uses HTTPS, installs prerequisites, configures a dedicated SSH identity, registers the host key, and verifies connectivity from the main node.
- Enrollment and readiness are distinct states. Existing Docker installations, workloads, and unrelated SSH configuration must be preserved.
- Workloads have explicit node placement. Compose stacks stay on one node. Cross-node networking is explicit.
- Public workers handle ingress/TLS locally; application traffic need not pass through the main node.
- Applications continue running when the control plane is offline.
- Projects, environments, workloads, releases, operations, routes, storage, and backup policies form the domain model.
- Secrets are encrypted at rest and delivered only where needed. Per-node SSH credentials and pinned host keys are mandatory.
- Builds, backups, and other expensive operations run on workers. Logs and telemetry are bounded.

## Delivery order

1. Persistent node enrollment, generated setup command, worker installation, SSH verification, and capability probe.
2. Compose deployment with durable worker operations, per-workload locking, logs, and interruption recovery.
3. Dashboard, projects/environments, Git automation, local workloads, and routing.
4. Database and volume backups, tested restores, dedicated build nodes, and Coolify migration.

Workers target Linux amd64/arm64 with systemd and OpenSSH; automatic installers cover Ubuntu/Debian and supported EL distributions. Single-hop bastions use independently pinned SSH identities. A node with Docker access is a privileged infrastructure identity even when its SSH command is restricted.

Workload release rollback restores saved Compose configuration and retained local images; it does not reverse application data or database migrations. Backups stop the workload for consistency and reject storage shared with other running containers. Restore requires the current storage layout, creates a safety snapshot and leaves the workload stopped if recovery fails. Local backups do not protect against node loss; offsite backup passwords and the panel encryption key must be backed up independently. Cancellation stops the command and leaves already-applied container changes for inspection. Operation journals are retained for reconciliation and investigation; audit history follows its configured retention window and protects undelivered exports. Per-operation output and telemetry history are bounded, but operation history and worker journals use age/count retention with explicit exemptions for unfinished and referenced recovery/release/backup records.

Environment previews copy one production environment per branch name across selected repositories: matching branches build, everything else runs the production state pinned at creation, data is copied once from read-only sources into preview-owned storage, connections are recreated between the copies, and protected routes are published after every resource is healthy. See DEVELOPMENT.md for the exact semantics and limits.

Private connections are explicit, directional TCP grants from one source service to one target service port, enforced on workers by a per-node link gateway with dedicated internal networks per source hostname and per target, and pinned mutual TLS between workers. They do not replace or restrict shared networks, published ports or public routes. See DEVELOPMENT.md for the operating model and limits.

Notification channels reuse encrypted team infrastructure connections and durable operation/health delivery queues. Channels can select exact catalogue events, including backup/restore/drill outcomes, or retain legacy success/failure/health selection. SMTP channels reuse the instance mailer; generic webhooks support timestamped HMAC signatures. Telegram, ntfy, Gotify, Pushover, Matrix and Teams use the same bounded dispatch concurrency and retry limit. PagerDuty/Opsgenie require matching alert/recovery routes with stable incident keys and ordered delivery. Workload owners are current team members and convey no extra access; owner email routing requires a verified, enabled account. Node CPU, used-memory and data-filesystem disk threshold rules persist confirmation/repeat/recovery state and restrict delivery to selected channels, with at most 100 rules per team and 32 channels per rule. The evaluator accepts fresh worker samples independently of storage and shares those measurements with metric collection. Certificate-expiry and container restart/OOM/crash rules use sanitized workload-scoped worker observations, with intentional-operation/manual-stop and one-shot-job suppression. Managed ACME key material remains on the worker. Historical operation notifications remain subject to the historical-storage limitation above.

Telemetry persists bounded node/container snapshots in minute/hour/day tiers and redacted workload log entries with incremental cursors, replay deduplication, filters and page downloads. Instance administrators configure global metric/log age, row and accounted-byte caps and audit age/row retention; usage distinguishes logical accounting from physical PostgreSQL allocation. Collection and results are bounded, and missing samples and log gaps remain explicit. Operation retention coordinates worker journal acknowledgements with panel deletion while preserving reconciliation and retained references. Mount capacity reporting and scheduled cleanup use bounded previews, ownership/reference checks and explicit volume/non-Cove opt-ins. Merged live tails retain container identity and redaction. Advisory deployment capacity checks compare declared limits with measured free resources, historical sizing suggestions require enough recent samples, and configured node prices roll up by explicit equal-resource allocation without currency conversion. Opt-in managed proxy access logs provide bounded sanitized route traffic, and panel HTTPS checks feed uptime alert rules and opt-in public project status. Sealed log forwarding outboxes use bounded retries/retention, while a separately token-protected Prometheus export exposes fresh instance metrics. Network collectors run independently of deployment dispatch.

Backup locations additionally support native Backblaze B2 through the existing encrypted rclone repository transport. Calendar retention adds bounded daily, ISO-week and monthly snapshot tiers to keep-last, with explicit worker capability checks before applying deletion. Stopped-volume and PostgreSQL/MariaDB logical backups retain their existing paths. MongoDB replica-set archives and Redis/Valkey RDB snapshots stream directly from the live container into a separate encrypted restic data snapshot. A linked metadata snapshot captures the release; both are pruned together with replay-safe deletion. Publication requires a successful isolated restore using the source image, with a 2 GiB verification memory limit. A per-resource journal reconciles interrupted snapshot creation, and two private per-resource staging directories bound each dump to 64 GiB. Restore drills and isolated resource copies understand the linked snapshots. In-place restores validate first, retain a safety snapshot, journal the original running set, and leave failed restores stopped for explicit recovery. MongoDB in-place restore requires a standalone target or writable single-member replica set; multi-member backups can restore into a separate single-member resource. Redis/Valkey restores require standard `/data` persistence paths and regenerate append-only files from the verified RDB. Permission-gated, audited downloads stream database dumps or volume tar archives through restricted SSH without buffering on the panel. Raw uploads and configured S3 object imports are size-bounded and restored in isolation before becoming encrypted backup records; importing never overwrites the running source. A worker-wide transfer journal and ownership-scoped helper labels clean plaintext and interrupted helpers on restart. Host snapshot plugins and PITR use separate host recovery paths.

Panel self-backup and exact snapshot recovery run through a root host timer, while the panel remains a non-root container without Docker access. Administrator settings seal offsite credentials and independent encryption passwords; host-only signed requests receive opaque plans, opened through a restricted local CLI. Encrypted snapshots include the PostgreSQL dump, actual runtime credentials, installation Compose/Traefik files, certificates and immutable installation image IDs. Publication requires an isolated database restore, and retention bounds local/offsite history while preserving active recovery references. Pre-update snapshots are mandatory before image replacement; historical panels without the new API use an authenticated, non-secret local bootstrap plan. Recovery validates artifacts before stopping the panel, retains a fresh safety snapshot, restores matching database/images/configuration, cancels restored unfinished intents and pins previews for review. A private host journal resumes interrupted restores without requiring the panel to be running. Updates pause after recovery until an explicit review/resume. Host-loss recovery, cross-major PostgreSQL conversion, filesystem permissions and real offsite/provider behavior still require separately coordinated acceptance.

Optional filesystem-backed volume backups inspect the host mount namespace and use read-only Btrfs subvolume, ZFS dataset or traditional LVM snapshots. Containers pause only for snapshot creation and resume before encrypted repository copying; original mount identities remain in restore metadata. Unsupported layouts fall back to the existing stopped method before any snapshot mutation. Failures after creation fail the backup, and LVM validity is checked before publication. A private bounded journal and ownership-tagged resources coordinate cleanup with worker restart and a host systemd lease reaper. The panel receives only sanitized mount capabilities and backup-method results; host tools and kernel modules remain host prerequisites.

Resource-editor file browsing uses structured restricted RPC for running containers and attached Cove-owned volumes, with team/project/environment authorization, ownership checks, clean-path/symlink restrictions, bounded data, revision checks and action audits. The 32 KiB editor is independent of administrator-bounded binary streams, which check size/digest without buffering file bodies on the panel. File contents are ephemeral and non-cacheable; volume changes require stopped users and all access coordinates with worker operations/draining. Existing-file edits preserve inode metadata and are not durable deployment operations. Host package/firewall/provider changes and resumable workload moves use separate increments.
Managed HTTP routes optionally carry a validated policy for path prefixes, request/response headers, source CIDR restrictions, hostname redirects, ACME selection, sticky sessions and additional upstream Compose services on the same worker. Policies travel in the existing encrypted workload configuration and durable route journal; no separate route database is introduced. Policy-derived proxy object names make stale middleware/upstream configurations fail live confirmation. Workers advertise `route_policies`; older workers cannot deploy policies. This extension does not create replicas or change proxy entrypoints. Maintenance pages, custom status pages and forward-auth use a versioned route protocol and immutable, bounded worker helper snapshots. Traefik remains the traffic authority and uses only the owned helper; the helper accepts its proxy peer, validates and pins public auth DNS answers, and targets only captured same-workload containers for internal auth. The helper has no Docker socket, panel credentials or dependence on the panel for serving traffic. Journal rollback and live proxy revision confirmation cover helper replacement; retained auth settings survive partial route edits. Worker route-bearing state includes a downgrade guard that older workers reject rather than interpreting an unknown auth policy as public. The wire API remains the plain route model.

Uploaded TLS versions are immutable and scoped to a resource in a dedicated sealed certificate table; routes contain only a public certificate ID. The worker receives a frozen sealed-operation bundle, stores private immutable material separately from route JSON and confirms live SNI/fingerprint selection before accepting a change. All certificate names are checked against the resource's owned hostnames to prevent cross-resource shadowing in Traefik's shared TLS store. Conflicting cached ACME entries are privately archived and projected with a durable proxy-reload intent; the first switch or restoration can briefly restart the shared proxy, while later uploaded-key rotations remain dynamic. Existing account data and unrelated certificates are retained. Certificates and routes continue serving without the panel; expiry and renewal remain the certificate owner's responsibility for uploads.

Managed Origin CA issuers keep sealed CSR/key checkpoints on the panel, reserve exact or one-label wildcard hostname claims, and use only current team-shared Cloudflare zones. Unknown provider outcomes reconcile the persisted key instead of blindly issuing again. Initial certificates are selectable immutable versions; renewal applies through journaled route operations and rechecks grants before replacing references to the previous version. Issuer deletion does not revoke or remove installed certificates. Managed ACME DNS-01 shares the immutable-version/route-application model, with a fixed operator authority and explicit current terms consent. A separate sealed account identity and durable TXT intent outbox preserve mutation ownership across panel restarts, uncertain provider responses and issuer/resource deletion. Validation waits for TXT visibility; cleanup verifies exact ownership and never discards unresolved proof. Definitive refusals require explicit retry. The worker receives certificates, not DNS credentials or authority account keys. Wildcard routing and cached-ACME suppression require route protocol 4; explicit hosts outrank wildcard paths, and private key material remains outside route configuration. Certificate endpoints share the unified catalogue and live scoped-token checks. Full panel backups retain the sealed certificate and issuer tables; canonical/project exports expose only certificate references and metadata. Custom route header values and complete forward-auth destinations are redacted, with explicit preservation markers preventing a read/save cycle from dropping saved protections. Certificate-only renewal remains a recovery exemption from application deployment freezes and approvals.

Route reads hide basic-auth hashes. Omitted authentication in configuration or route updates preserves the existing hostname/path credentials; an explicit empty value removes them. Prefix changes with ambiguous previous credentials are rejected, keeping policy edits from silently exposing a protected route.

Runtime inspection exposes Docker health separately from lifecycle state and reports exit codes plus successful Compose init completion. Job schedules use a saved IANA timezone (UTC for existing schedules), with embedded timezone data in the control plane. The legacy guarded-deploy option still tests a stateless candidate before ordinary Compose replacement and can briefly interrupt traffic. Opt-in rollouts instead isolate Compose generations within the owned workload project, health-gate every replica, switch journaled Traefik weighted services, then drain and remove the captured old containers. Current release snapshots retain original-to-generation service mappings so logs, backups, private grants, promotion and preview inventories resolve the active containers. Blue/green and canary keep both generations until explicit promote or abort. The traffic decision and operation status are persisted together under the cancellation lock; restart recovery restores old traffic before that decision and completes cleanup after it. Staged traffic survives panel and worker restarts. Ineligible Compose configurations fall back to guarded replacement with an explicit reason and ordinary Compose scaling; replica overrides apply only to eligible parallel replacements.

Image lifecycle checks are durable, cancellable metadata operations on upgraded workers. Background checks use the existing workload lock and queue, with at most four background checks at once, and run hourly for deployed, non-stopped services outside managed previews. Workers compare registry manifests and platform configuration digests against deployed images, using the resource's team registry connection. Jobs are excluded so metadata checks cannot consume scheduled run slots. Explicit image refresh remains an ordinary approved/frozen deploy operation with forced pulls; existing releases remain available for rollback.

Separate build operations build Compose services on their resource's worker and publish verified immutable references through the selected registry connection. They reuse encrypted requests, shared variables, Git credentials, file secrets, bounded logs and per-workload locking. Unique operation/service tags prevent concurrent builds from exchanging image identities; each published manifest is checked against the built image before recording success. Builds do not replace containers, routes or the current release. Temporary tags and inputs have an ownership-checked cleanup journal; interrupted or partially published artifacts remain inspectable in the registry. Build nodes, a managed registry and non-Dockerfile build engines are outside this implementation.

Scheduled job runs journal the designated service, absolute execution deadline and cleanup outcome before starting containers. Jobs disable container restart policies, observe the designated service rather than dependency exits, capture bounded redacted stdout/stderr, and stop all run-owned services before releasing the workload lock. Restart recovery observes the same containers without executing the job again; an unknown legacy outcome is reported as interrupted after cleanup. Schedules can skip overlaps, coalesce one pending run, or cancel a running job and wait for confirmed cleanup before replacement. Existing operation notifications report job failures.

Optional unhealthy-container restarts use the existing durable control-plane operation queue and workload locks. The monitor checks Docker health about once a minute while the panel is online, skips manual stops, jobs, previews and staged rollouts, and revalidates admission after the worker read. Restarts have a five-minute resource cooldown and at most three queued attempts in a rolling hour. The worker rechecks health under its workload lock and restarts only running unhealthy containers; healthy, starting and stopped containers are preserved.

Environment suspension keeps canonical desired intent on the environment and per-resource operation checkpoints in PostgreSQL. It cancels prior work, waits for worker-confirmed cleanup, then journals the exact containers and restart policies on each worker. Paused routes keep their authentication and hostname ownership while returning 503. Resume restores only captured service intent, preserving manual stops, completed init containers and staged generations; jobs resume their calendar without replaying missed ticks. Worker recovery retains workload locks until the journaled outcome is confirmed. A failed resume remains explicit and retryable instead of silently recreating containers or reporting an active environment. Shared admission and queue guards prevent automatic deployments from bypassing a pause.

Idle sleep is opt-in for entirely request-driven services whose traffic passes through managed HTTP routes. A per-resource worker helper measures complete request lifetimes, including streaming responses and WebSockets. Traefik keeps authentication, headers, allowlists, weighted traffic and TLS in front of the helper. Separate internal front/backend bridges pin the proxy peer and owned literal upstream addresses; the helper receives neither the Docker socket nor the general worker RPC socket. Its only worker connection is a scoped, token-protected wake Unix socket. Awake applications continue serving with the panel or worker offline; waking requires the worker.

The helper atomically quiesces only after the idle interval and zero active requests. Worker-local sleep/wake operations reuse durable suspension snapshots, workload locks, fixed health deadlines and exact container identities. Requests arriving during sleep coalesce onto one wake attempt per episode and wait for health plus refreshed upstream addresses. Failed wakes leave containers stopped and require explicit Start after repair. Manual stops and environment pauses cannot be bypassed by a request; an environment resumed over a previously sleeping resource restores that prior idle intent. Policy changes journal their route outcome, and the control-plane setting commits only after worker confirmation. Idle helpers share Cove's existing helper-network pool with separate ownership labels; automatic journals retain the latest 100 per resource plus current intent, without pruning public operation history.



Optional single-hop SSH bastions have separately pinned host keys and independently sealed forwarding identities. Forwarding does not relax worker forced-command keys, and both hops authenticate before restricted RPC or raw transfer. Authentication-key rotation stages a second restricted key, proves a fresh connection, commits the panel identity and only then removes the old key. One sealed pending/last result per node and one bounded worker journal/staging file make lost receipts and restart recovery explicit. Confirmed host-key changes refuse connections and feed assigned-team alert routing; ordinary network errors do not clear them. Operators configure the dedicated bastion account's forwarding restrictions outside Cove.

PostgreSQL point-in-time recovery uses a separate WAL-G archive in the resource's selected storage, encrypted with an independent sealed key. A bounded worker helper streams a physical replication slot through a private mounted Unix socket and an authenticated local rclone S3 bridge; the panel gains no Docker privileges. Enabling/disabling the socket requires a PostgreSQL restart, while subsequent base backups and WAL capture stay online. Base images and operation references remain protected. Per-resource age/count/byte/object bounds, a checkpoint-enforced source slot budget and ownership markers prevent unbounded retention or cross-resource deletion. Recovery windows require a complete archived transaction heartbeat and per-base WAL integrity checks. Restores always replay into fresh isolated storage, verify promotion and a normal administrator login, and publish an offline resource with new protected credentials and no public endpoints. Source data and authentication rules are preserved. Durable cleanup journals retain failed copy storage for inspection and remove only owned temporary helpers on restart.

## Completion requirement

The user explicitly requires a fully fleshed-out, production-ready product, not a proof of concept. The delivery order above describes implementation increments, not acceptable stopping points. Release acceptance must cover authenticated dashboard workflows, durable execution and recovery, secret handling, Git/build deployment, routing, backup/restore, installation/upgrades, and real Linux validation. Unverified production behavior must remain explicitly identified.

### Git provider boundary

GitHub clone credentials, repository and branch listing, webhook signature verification, pull-request decoding and commit-status publishing are accessed through the control plane's internal `gitProvider` interface (`internal/control/git_provider.go`). Installation ownership and team sharing checks remain at the handler/deployment boundary; durable webhook deduplication, commit pinning, superseding and preview reconciliation remain in their existing queues. Clone tokens continue to request only repository-scoped contents read access. Commit-status publishing requests a separate repository-scoped statuses write token; clone tokens never gain write permissions. Automatic GitHub feedback is opt-in per source, inherited by its PR previews. A separate retry queue publishes immutable-commit statuses, Deployment records and App-authored preview comments without failing deployment execution.


### Additional Git sources and CI triggers

Team-owned Git connections support GitLab, Gitea-compatible servers (including Forgejo and Codeberg), and Bitbucket Cloud. Credentials and webhook signing keys are sealed; provider repositories have connection-scoped local identities, including Bitbucket UUID mappings. API calls require trusted HTTPS, public DNS/IP destinations and no redirects. Signed pushes enter the existing encrypted, deduplicated deployment queue with immutable commit revisions and service-push superseding. PR/MR events use the existing isolated preview lifecycle; forks remain excluded. Optional commit statuses and provider-account-authored preview comments retry independently of deployment execution. GitLab signing requires GitLab 19's signing-token support; plain secret-token headers are not accepted.

SSH sources use a generated Ed25519 identity per workload and an operator-supplied host public-key pin. The control plane seals the identity and injects it only into encrypted operation payloads. The worker uses a temporary identity and known-hosts file, refuses ambient/password authentication and unknown host identities, then removes the credentials on success or failure. Clones need their own generated deploy key. HTTPS credential helpers are restricted to the source's protocol, host and port.

Automatic source triggers can follow the saved branch, a tag glob, or published releases resolved to tag commits. Manual deployment continues to use the saved branch. GitHub, GitLab and Gitea-compatible release events are supported; Bitbucket Cloud has no native release event and uses tags. Inbound CI/CMS hooks are separately scoped credentials with a 90-day lifetime, ten new deliveries per minute, stable delivery receipts and creator-grant revalidation at receipt and dispatch. Rotation/revocation removes unsubmitted hook requests. The reusable composite Action under `.github/actions/deploy` triggers a hook and polls its durable receipt without placing credentials in URLs or following redirects.

### Variables and external secret providers

Saved `.env` import merges named keys under the resource configuration lock and blocks edits during an active operation. Parsing is bounded, does not execute shell syntax or expand dollars, and preserves quoted/multiline values. Export is an explicit editor-only POST, audited before disclosure and sent with `Cache-Control: no-store`; it contains saved values and references rather than resolving external secrets.

Deployment variable resolution composes encrypted workload values, existing shared/resource bindings and team-scoped external secret sources. References have the form `{{secret.CONNECTION_ID:REFERENCE}}`. Provider credentials are sealed independently and never returned by connection reads or writes. Resolved values are bounded, treated as opaque, redacted by the worker, and sealed into the operation's prepared payload; retries reuse that snapshot. Missing, revoked, malformed or inaccessible references fail deployment with the variable name and a sanitized explanation. Preview plans require explicit decisions for external secret and shared references rather than silently copying production credentials.

The resolver supports Vault/OpenBao KV v2, Infisical v4, Doppler, 1Password Connect and optional vendor CLI sources for 1Password service accounts and Bitwarden Secrets Manager. HTTP sources use trusted HTTPS, public-address DNS checks, bounded responses and no redirects. CLI sources use credentials only in isolated child environments, private temporary configuration, bounded output, discarded diagnostic output and read-only commands. Service-account tokens are limited to the official 1Password cloud domains; Bitwarden supports the US/EU clouds. Vendor CLIs are operator-installed prerequisites, not bundled dependencies, and missing binaries are reported clearly.

Workers advertising `builtin_variables` add seven deployment defaults: `COVE_FQDN`, `COVE_URL`, `COVE_COMMIT_SHA`, `COVE_BRANCH`, `COVE_ENVIRONMENT`, `COVE_PROJECT` and `COVE_RELEASE`. The actual checked-out commit supplies the SHA. Defaults are available to Compose interpolation and inserted into missing service environment/build-argument entries, preserving explicit settings. Retained release state records which metadata values are public so ordinary names do not corrupt secret-redacted logs. Older workers keep their existing behavior and the API reports built-ins unavailable until upgrade and verification.

### Public automation interfaces

A versioned `/api/v1` catalogue registers real handlers and generates OpenAPI 3.1 request/response schemas; Swagger UI is bundled in the frontend. Personal/team token credentials are stored only as hashes with explicit scopes and expiry. The token permission catalogue is centralized for reconciliation with custom roles; every request also revalidates the creator's active account, current membership and grants. Legacy workload-scoped tokens remain isolated to their existing routes. Explicit saved/resolved variable disclosure is editor/scoped and audited before response; ordinary variable reads expose only existence and a keyed revision.

The same `cove` binary retains no-argument server startup and supplies opt-in client commands with private named contexts, deploy/wait, polling logs, bounded container exec, environment pull/push/local-run and pinned temporary service forwarding. One-off exec selects running Compose-owned containers and bounds response output/wait; a timed-out Docker exec may continue inside the container and is never automatically replayed. Runtime service labels support replica selection without trusting user-provided container IDs.

MCP is an administrator-enabled, off-by-default stateless HTTP surface implemented with the official SDK. Scoped-token-only resource/tool calls reuse the public API authorization boundary and existing operation queue. An independent Terraform/OpenTofu protocol6 provider manages projects, environments, workloads, variables and complete public route sets through the same API; it does not implicitly deploy or migrate application data. Native provider fixtures are isolated from real accounts and hosts.

Compose compatibility is checked against the native plugin with local file fixtures, including retained-release round trips. Worker transforms distinguish resolved Compose's escaped representation from raw preview configuration, preserving literal dollars through limits, secrets, networking, promotion and release snapshots. Snapshots remove profile conditions after service selection so rollback restores that selection. Primary-file null network names are normalized in an adjacent private copy. Restricted PR previews are validated before any Compose command, including built-in variable resolution.

## Declarative project configuration

`projectConfiguration` is the canonical `cove/v1` representation shared by strict import, encrypted saved drafts, ZIP export, environment comparison, GitOps and declaration drift. Resource configuration reuses `workloadInput`; stable project keys map to resource IDs without renaming the physical Compose project. Draft apply locks declarations, checks an opaque reviewed version and current grants, and saves changes transactionally. It upserts without implicit deletion or deployment; existing routes retain worker-mediated claim/recovery semantics. Shared variables and resource bindings retain explicit scope/source checks. Portable exports are audited secret reads and omit managed provider/private-key credentials. Repository support files/build contexts remain tied to the pinned source checkout.

Ordered Compose selections travel inside the sealed queued worker request, including webhook, scheduled, promotion and environment-preview paths. Workers stage inline bundles privately or validate selected repository paths against the checkout root, merge the ordered files/profiles through native Compose, then apply the existing infrastructure transforms. Metadata reads reveal no private file content. `operations.declared_payload` preserves a separate immutable declaration for deploy review while the prepared execution payload gains resolved variables and short-lived credentials.

GitOps references a persistent Git resource and obtains cove.yaml through bounded worker source-file inspection without invoking Docker or retaining the inspection checkout. Sync stages the same reviewed draft flow. Automatic apply is opt-in and runs separately from operation dispatch under a currently verified creator's grants; it saves configuration without deploying applications. Desired declarations remain sealed, and drift responses contain field names only. Runtime drift is a separate worker inspection against its last recorded successful-operation baseline, returning changed categories rather than values. Unknown/busy/unavailable baselines are distinct from an unchanged runtime. Auth integration must map current editor-level configuration exports to the auth track's secret-read permission and reconcile the centralized `configuration:write` scope.

## Migration and adoption

Resource moves retain the workload identity, worker and routes. A reviewed HMAC version binds the current sealed configuration and destination declaration; a serializable transaction checks both placements, quotas and explicit dependencies before changing all placement columns together. Workload mutations hold shared PostgreSQL admission guards through reauthorization and completion, while moves take the exclusive guard, including across API replicas. Guard admission reserves pool connections for handler transactions. Access follows destination grants and policies. Cross-team transfers require administration on both teams and revoke resource tokens, deploy hooks and webhook secrets. Team-scoped automation keys cannot expand their authority through a transfer. References and infrastructure connections that cannot safely follow the resource block the move until explicitly detached or materialized.

Coolify import discovery accepts operator-supplied native resource/environment API exports, retains only an allowlist inside an expiring sealed session, and returns metadata only. Mapping produces the same cove/v1 declaration used by ordinary reviewed drafts. A bounded worker Compose config-only pass validates and resolves standalone files; private string fields become sealed interpolation variables. Applying the resulting draft saves configuration without contacting, starting, stopping or modifying the source. Missing files, ambiguous physical volume names, masked values and unsupported build packs are refusals, not guessed defaults.

Existing Compose adoption is instance-admin only. Discovery returns project/service/count metadata. Planning checks original local Compose files, container creation hashes and consistent images, then creates a canonical snapshot pinned to actual image IDs. Confirmation reserves resource identities and source-project claims before contacting the worker. Pending resources are read-only, with database guards preventing edits and queued operations. Each worker records a durable private adoption intent, release snapshot, project-name registry and runtime baseline without restarting containers. Docker selectors and lifecycle commands use the registered physical project name; ordinary resources retain their cove-ID names. Interrupted calls resume the same adoption, and an explicit refresh reconciles registered ownership before updating pending source reviews. Completed adoption records truthful adopt operations and team audit events. The initial runtime baseline accepts manual overrides already present; a Compose creation hash alone does not establish their absence.

Adoption leaves source proxies, middleware, automation and application data in place. Pausing the source manager is an operator attestation, never an automated source mutation. Source-file availability, manager cleanup, routing/data cutover and recovery require separate acceptance; the existing same-host migration scripts remain independent operator tools.

## Workspace UX and panel paths

The workspace search API filters its selected team and current project/environment grants before returning names and navigation paths. Bulk actions reuse the individual operation authorization/admission/queue boundary and produce a result per selection; queued is not deployment success. Tags belong to resources; pins and dismissed first-run progress belong to a user and team. The dashboard activity feed returns current accessible operation/configuration metadata without actor or configuration values.

Project/resource notes are sealed at rest, version checked, and rendered as CommonMark with raw HTML/dangerous links disabled and images removed. A project editor may explicitly enable a hash-only, expiring, revocable public status token. Public output contains an operator-chosen title and aggregate deployment states only, not resource names, internal IDs, configuration, notes or live health. Rotation invalidates previous badge/dashboard links immediately.

Team display timezone defaults to UTC; a user may override it or inherit the selected team's value. Backup schedules use UTC; jobs and deployment windows use their saved IANA zone. The UI distinguishes these schedule zones from display time. The control binary embeds timezone data.

COVE_PUBLIC_URL accepts an HTTPS origin with an optional simple path, for example https://panel.example.com/control/cove (no trailing slash). One mount boundary strips it before existing handlers and prefixes local redirects. Callback, webhook, enrollment and notification URLs retain the full public URL. Browser CSRF checks compare the origin only. Secure HttpOnly __Host- cookies deliberately retain their required Path=/ and host-only scope. The frontend gets its base path from server-injected metadata/base href; one build works at root or below a path. The client/CLI/provider preserve that path. Root /healthz remains available for container liveness.

The trust/integration merge uses the fixed permission catalogue for authorization and exposes its exact resource permissions alongside existing UI aliases. API scopes cap that catalogue and revalidate current grants. Runtime deployment admission resolves a temporary preview back to its source environment; canonical project configuration carries the same full deployment policy. Project configuration writes, imports and adoption do not implicitly deploy. Panel path stripping precedes network policy/auth route classification, while WebAuthn origins use scheme/host and OIDC callback URLs retain the full panel path. Public aggregate status remains a separate anonymous, revocable capability under the panel network policy.

The operations merge uses that same catalogue: backup configuration and imports require backup management, configuration editing and secret reads; archive downloads require backup management and secret reads. File access remains instance-administrator-only with explicit configuration/secret capabilities. Notification and forwarding credentials require team administration plus configuration editing and secret reads. Metrics scrape capabilities retain their issuing administrator and revalidate account, lockout and required second-factor enrollment on every request. Anonymous uptime status exposes only selected public labels and results, separately from the aggregate deployment share page.

Operational and security outcomes share the notification delivery queue. Outgoing generic and audit webhooks sign the timestamp, a dot and the exact body using the same HMAC scheme. Audit retention has one canonical period and never removes undelivered export records; operation pruning also retains reviewed-draft references, pending adoption and deployment governance history inside that period. Selected outbound proxies apply to HTTP providers, SMTP, uptime probes, TLS log/audit forwarding, worker storage helpers and panel recovery plans. Public endpoint validation, TLS verification and pinned SSH storage keys remain in force.

Panel updates verify signed images and channel/schema ordering before taking the operations pre-update snapshot, then drain and replace the panel. Offline bundles authenticate the recovery companion scripts as well as the installer and updater. Explicit snapshot recovery restores its captured database/configuration with retained local images; it is separate from an automatic binary rollback across a changed schema. Backup, restore, cleanup and panel recovery are maintenance exemptions from application deploy freezes; configuration-only GitOps/import apply and restart-free adoption do not deploy.
CPU autoscaling uses the existing container CPU metrics and immutable rolling-release snapshots. The panel persists three generation-matched observations, refuses stale or incomplete replica metrics, and queues an ordinary durable deployment after sustained pressure or sustained low load. Explicit CPU limits normalize Docker CPU percentages; explicit CPU and memory limits reserve the configured maximum replica budget. Deployment approval, freezes, windows, cancellation and worker recovery retain their normal semantics. Scaling rechecks the source generation, never falls back to guarded replacement, and updates saved replica counts only after the worker confirms the traffic handoff. A dedicated submission RPC prevents an older worker from treating the request as an ordinary rebuild.


## Merged deployment lifecycle boundaries

Rollout promotion uses the same preview-aware approvals, freezes, recurring windows and team deployment slots as deploy and rollback. CPU scaling queues an ordinary deploy of retained immutable images through that gate. Abort, retained-container resume/wake and unhealthy restart are recovery actions; they require the normal catalogue permissions but do not create a new release or wait for a deployment freeze. Build/publish produces images only; a subsequent deployment is separately admitted. Environment suspension and idle holds also guard restore/drill and reviewed moves. Dump import writes the backup repository, never live database data; restoring it uses the normal guarded restore action.

A committed-deployment view distinguishes active declarations from waiting or aborted candidates. Explicit promotion resolves to its original candidate declaration, including immutable revision metadata. Configuration review, environment comparison and export use those committed declarations. Runtime drift baselines follow promotion, abort, recovery and replica changes. Worker selectors use an adopted resource's physical Compose project while telemetry keeps its logical service labels; gateway and route helpers remain outside those selectors. Capacity accounts for requested replicas and quotas reserve autoscaling maxima, with temporary overlapping-generation capacity still explicit.

Structured route policy fields round-trip through the canonical manifest and Terraform. API views, portable exports, history and draft diffs omit bcrypt entries and forward-auth destinations, including service paths. Existing destinations are retained by route identity when a writer omits private fields; ambiguous older writes fail instead of dropping protection. External forward-auth uses pinned public-address validation before the selected outbound proxy, and proxy changes reconcile running helpers before succeeding. The worker's private BuildKit builder follows the selected proxy; Docker-daemon image pushes and explicit pull-and-redeploy require matching daemon proxy settings, configured by the operator rather than changed by a request.


Git provider commit/deployment feedback treats a staged candidate as running until its traffic promotion succeeds. A successful abort or stop that aborts the candidate reports it inactive; failed decisions leave the report pending. GitHub App and other connected providers use the same outcome mapping.


Managed database resources retain their typed descriptor in committed worker release snapshots and encrypted backups, so separate recovery cannot become a stateless service. Database maintenance shares deployment governance and unified grants; metadata-only bindings are distinct from password/URL secret reads. Base canonical imports generate credentials while existing-resource drafts preserve sealed settings. Online database backups reuse the operational dump/stream and restic paths; database version copies share the bounded native dump runner. Unresolved maintenance is protected from operation and worker-journal retention.

Directory-managed access and local grants share the fixed permission catalogue and membership provenance model. Versioned administration uses personal instance-administrator scoped tokens; SCIM has its own sealed instance bearer credential and mutation-version recheck. Deprovisioning atomically revokes personal credential surfaces and owned automation. Both deployment-status links and uptime status pages, plus scheduled jobs, record creators and revalidate current permission/account policy through `cove_automation_allowed`; scheduled executions retain durable owner provenance for revocation and cancellation. Unknown legacy ownership stays suspended until an explicit claim, while local CLI contexts retain only invalidated credentials. Directory outcomes reuse operations notification/audit delivery and retention. The panel base-path wrapper owns relative callback redirects; provider-facing absolute callback and SCIM metadata URLs use the full public URL.

Host security maintenance uses allowlisted worker RPC and a bounded trusted host helper for cached package/security/reboot inspection. An explicitly confirmed Cove-owned native timer delegates security updates to the host package manager without changing unrelated schedules or expanding panel privileges. Host state is limited to a fixed owner marker, service/timer pair and two bounded staging claims.

Node firewall changes use an owner-scoped nftables application-port table, management-port exclusion, revision-bound preview, an independent native timed revert and a fresh panel-to-worker connectivity check before confirmation. A protected boot service restores committed policies and excludes new management listeners; external tables remain untouched. The native recovery executable and single preimage journal are bounded independently of operation history.

Cloud server provisioning seals provider tokens and queues a bounded durable job before an external create request. Hetzner, DigitalOcean and Vultr have fixed TLS API origins. Lost acknowledgements reconcile owned markers using reads; creation is never retried automatically. Automatic enrolment reuses the existing one-use installer token and pinned worker identity. Node removal and abandoned tracking never delete provider servers.

Team and environment resource defaults fill missing deployment limits while preserving Compose declarations and explicit per-service overrides. Capacity-based placement suggestions read fresh team-assigned node measurements and never choose or move a resource automatically.

Per-service GPU selection extends existing sealed resource limits and retained release configuration. Explicit native inspection reports bounded NVIDIA/CDI identities; the worker revalidates selected devices and Docker driver availability before deployment. No device credential, host driver installation, implicit all-GPU allocation or additional persistent inventory store is introduced.

Workload moves persist one durable panel intent and owner-verified source/destination worker fences. Named volume data, immutable images, resource metadata, retained operation journals and local encrypted backup repositories stream directly between pinned worker connections through the panel. Placement changes only after destination health checks; rollback proves destination stoppage before restoring original source restart policies. Docker daemon identities remain bound to the accepted preview across retries.

Node-wide managed listener changes are reviewed static-proxy transactions, serialized with route edits. The worker snapshots the immutable launch and all pinned helper network peers privately, validates the desired static configuration against read-only original mounts, retains the original proxy through activation, and persists the commit before cleanup. Startup recovery restores uncommitted changes and completes committed ones before normal ingress reconciliation; active recovery holds conflicting operations. Plans and API status expose only settings and change metadata. Stock CLI and Compose file launches retain their distinct configuration sources, including the panel-copy startup step and persistent ACME data. Static changes briefly interrupt shared proxy connections; ordinary route changes retain dynamic reloads. A stopped proxy stays stopped, with an inert publication probe validating its proposed bindings; saved installed launch state also recreates a missing proxy without losing managed listeners.

Private HTTP routes carry only non-secret visibility and listener identifiers. The worker requires a matching reviewed HTTPS listener, verifies its actual bindings, and generates explicit private routers plus public host-wide denials. Direct-source CIDR checks are independent of forwarded headers; existing authentication and user allowlists remain in the chain. Custom shared TCP precedence, implicit/private custom HTTP listeners and reserved priorities are refused rather than allowed to bypass the route. Listener changes hold the same hostname-claim lock as resource edits and check saved and pending references. Versioned submission and protected on-disk policies prevent downgraded workers from regenerating public routes; unchanged older-client saves retain privacy. Real network/firewall/Tailscale acceptance remains separate from local binding and source-address tests.

Raw TCP/UDP routes use protocol-matched dedicated listeners and literal owned container endpoints, with node-wide saved/pending ownership claims. They share durable route decisions and rollback with HTTP but do not use host rules or HTTP security/TLS fields. TCP source restrictions and private bindings remain separate checks; UDP relies on reviewed bindings and external firewall policy. Raw routes disable idle accounting and parallel weighted rollout eligibility. Lifecycle operations refresh ordinary Compose endpoints as well as generation endpoints. UDP retirement replaces the pinned proxy's retained handler with a non-forwarding destination before removing the router. HTTP upstream timeouts are non-secret per-route servers transports; WebSockets retain automatic upgrade behavior and their active sessions are not governed by pooled HTTP idle timeouts.

Node listener replacement, traffic proxy changes, certificate-cache proxy restarts, node moves and native host update runs share an owner-protected process lock. Durable moves and unsettled proxy journals retain their holds between calls and across restarts. Worker draining counts these transitions before declaring a safe update boundary. Existing direct-package host timers require an explicit Host security updates policy save before new listener, traffic or move mutations; the saved timer invokes the installed trusted worker helper and defers while node recovery is pending. Saving or disabling the policy remains possible during recovery. No package update or firewall opening is implicit in a listener change.

Private HTTP routes are excluded from public DNS publication, uptime probes, public uptime status results and external links. Already configured public DNS and previously issued shared-store certificate names are not automatically erased. The shared TLS store can serve a private certificate's names on public HTTPS when a client already guesses its exact SNI; HTTP access remains denied. This accepted limitation is disclosed beside the private-route certificate choice. Public certificate issuers refuse private route names and recheck current connection-owner account policy and receiving-team zone grants. CA traffic uses the selected outbound proxy and remains confined to the operator-configured HTTPS authority. Certificate renewal is a recovery exemption from deployment freezes, windows and approvals; ordinary application deployments and node moves retain admission. Full database backups include the sealed certificate, account and DNS-intent tables under the existing panel key; portable exports, history and diffs contain only certificate references, never key, CSR or CA-account state.

Node listener administration is instance-administrator-only, including personal scoped tokens with nodes:manage. Resource listener metadata requires View; route changes require Edit configuration. The versioned API and generated OpenAPI share these handlers. Terraform routes_json and canonical project declarations retain listener, transport, visibility, timeout and certificate-reference metadata. Dedicated listener CLI, Terraform resources and MCP tools are not exposed; the generic versioned CLI API can call the endpoints. Node move previews validate destination listeners and reserve them until the move finishes. Shared proxy publications also appear in firewall inspection; external reachability and firewall changes remain explicitly reviewed actions.
